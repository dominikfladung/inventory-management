Data flow

  1. User changes a filterFilterBar updates the shared singleton refs in useFilters.js: period, location, category, status.
  2. View reacts and calls the API clientgetCurrentFilters() builds the filter object; api.js drops values equal to all and sends the rest as query params.
  3. FastAPI route receives the requestOptional query params are bound; apply_filters and filter_by_month narrow the in-memory lists (quarters like Q1-2025 expand to months).
  4. Response is validatedPydantic response_model checks the shape before JSON is returned.
  5. View stores raw data in refs, derives the restRefs such as allOrders and inventoryItems hold server data; computed properties produce chart series and totals.

Startup path: server/data/*.json is read by mock_data.py when the server imports it, so data resets on every restart.

Observations

Client and server are out of sync. api.js calls /api/tasks (GET, POST, PATCH, DELETE) and /api/purchase-orders, but server/main.py defines no such routes, although it already has the PurchaseOrder models and loads purchase_orders.json. Those client features would return 404 today.

Stateless server

  • All data is read-only module-level lists, so there is no persistence or write path yet.

Hard-coded API URL

  • API_BASE_URL is http://localhost:8001/api in api.js; CORS allows any origin.

Test coverage

  • Backend only; the frontend has no test setup.
